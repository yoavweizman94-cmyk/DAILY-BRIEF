# הקמת אתר פרטי — מדריך מלא

מדריך צעד-אחר-צעד. **אתה עושה רק את מה שמסומן "אתה"** — כל השאר עליי.

מחולק לשלושה שלבים עצמאיים. אחרי שלב 1 כבר יש אתר עם חובת התחברות; שלב 2
מוסיף דומיין משלך, ושלב 3 סוגר את הפרצה שהתוכן פומבי ב-GitHub.

---

## למה בכלל צריך לעבור

האתר היום מתארח ב-GitHub Pages. **GitHub Pages לא יודע לבקש התחברות** — אין
שם מנגנון כזה בכלל. כל מי שיש לו את הקישור רואה הכל.

לכן עוברים ל-Cloudflare: הוא מארח את האתר בדיוק כמו היום, אבל אפשר להעמיד
לפניו שומר שדורש הזדהות. השומר הזה נקרא **Cloudflare Access**, והוא חינם
עד 50 משתמשים.

איך זה נראה למי שנכנס: הוא מקבל מסך שמבקש כתובת מייל, מקבל למייל קוד בן שש
ספרות, מקליד אותו ונכנס. אין סיסמה לזכור ואין משתמש ליצור. אם הכתובת שלו
לא ברשימה שאתה מאשר — הוא לא מקבל קוד בכלל.

# שלב 1 — אתר מוגן (30 דקות, בלי דומיין)

בסוף השלב הזה יהיה אתר בכתובת כמו `forest-brief.pages.dev` שדורש התחברות.

## 1.1 — חשבון Cloudflare · **אתה**

היכנס ל-<https://dash.cloudflare.com/sign-up> והירשם עם המייל שלך. חינם,
בלי כרטיס אשראי.

אם כבר נרשמת — דלג.

## 1.2 — יצירת API token · **אתה**

זה מפתח שמאפשר לי לפרוס את האתר לחשבון שלך בלי לדעת את הסיסמה שלך.

1. בפינה הימנית העליונה של הדשבורד לחץ על אייקון הפרופיל → **My Profile**
2. בתפריט הצד: **API Tokens**
3. **Create Token**
4. מצא את השורה **Edit Cloudflare Workers** ולחץ **Use template** לצידה
5. גלול למטה. שם צריך למלא שלושה סעיפים:

   - **Account Resources** — כבר מוגדר לחשבון שלך. אל תיגע.
   - **Zone Resources** — בתיבה האמצעית שכתוב בה `Specific zone`, שנה
     ל-**All zones**.
   - **Client IP Address Filtering** — **השאר ריק לגמרי.** אל תלחץ
     "Use my IP". הטוקן ישמש שרת של GitHub שכתובת ה-IP שלו משתנה בכל
     ריצה, וכל נעילה ל-IP תשבור את הפריסות.
   - **TTL** — השאר ריק. תאריך תפוגה ישבור את המערכת ביום שהוא פג.

6. **Continue to summary** → **Create Token**
7. **הטוקן מוצג פעם אחת בלבד.** העתק אותו עכשיו לאיזשהו מקום זמני.

## 1.3 — מציאת ה-Account ID · **אתה**

מזהה של החשבון שלך. הדרך הכי פשוטה: תסתכל על **שורת הכתובת של הדפדפן**
כשאתה בדשבורד של Cloudflare. היא נראית כך:

    https://dash.cloudflare.com/<כאן-יופיע-רצף-של-32-תווים>/...

הרצף הארוך אחרי `dash.cloudflare.com/` הוא ה-Account ID. העתק אותו
**מהדפדפן שלך** — לא מהדוגמה כאן.

## 1.4 — שמירת השניים ב-GitHub · **אתה**

1. פתח <https://github.com/yoavweizman94-cmyk/DAILY-BRIEF/settings/secrets/actions>
2. **New repository secret**, ומלא פעמיים:

   | Name | Secret |
   |------|--------|
   | `CLOUDFLARE_API_TOKEN` | הטוקן מסעיף 1.2 |
   | `CLOUDFLARE_ACCOUNT_ID` | המזהה מסעיף 1.3 |

**תגיד לי כשסיימת** — ואז אני מקים את פרויקט ה-Pages, מעביר את הפריסה
מ-GitHub ל-Cloudflare, ומריץ בדיקה.

## 1.5 — הפעלת ההגנה · **אתה** (בממשק) — אני אלווה אותך

אחרי שהאתר עלה:

1. בתפריט הצד של Cloudflare: **Zero Trust**
2. בפעם הראשונה הוא מבקש לבחור שם צוות (כל שם) ותוכנית — בחר **Free**.
   הוא מבקש פרטי תשלום לאימות בלבד ולא מחייב.
3. **Access → Applications → Add an application → Self-hosted**
4. שם: `FOREST Brief`. בשדה הדומיין הזן את כתובת האתר.
5. במסך המדיניות: **Action = Allow**, ובתנאי בחר **Emails** והזן את
   הכתובות שאתה מאשר, אחת בכל שורה.
6. **Save**

מרגע זה כל כניסה דורשת קוד למייל, ורק כתובות מהרשימה מקבלות אותו.

# שלב 2 — דומיין משלך

## 2.1 — קניית דומיין · **אתה**

הכי פשוט לקנות בתוך Cloudflare עצמו, כי אז אין מה לחבר ידנית:

**Dashboard → Domain Registration → Register Domain**

חפש שם פנוי. `.com` עולה בערך 10 דולר לשנה. Cloudflare מוכר במחיר עלות
בלי תוספת רווח וכולל הסתרת פרטים אישיים.

אם תעדיף רשם אחר (GoDaddy וכדומה) — אפשר, אבל אז תצטרך להעביר את
ה-nameservers ל-Cloudflare וזה שלב נוסף. תגיד לי ואלווה אותך.

אני מחבר את הדומיין לאתר ומעביר אליו את ההגנה.

# שלב 3 — סגירת הפרצה: תוכן פרטי

**זה השלב החשוב ביותר מבחינת אבטחה.** גם אחרי שלב 1, הריפו ב-GitHub
ציבורי — כלומר כל הברייפים קריאים שם ישירות, וגדר סביב האתר בלבד לא שווה
הרבה.

## למה לא פשוט להפוך את הריפו לפרטי

כי אז דקות ה-GitHub Actions מפסיקות להיות חינם. מדדתי: המערכת צורכת
150–310 דקות ביום, והמכסה החינמית בריפו פרטי היא 2,000 בחודש. החריגה
תעלה 20–60 דולר בחודש.

הפתרון: **הקוד נשאר ציבורי** (ולכן ה-CI חינם), **התוכן עובר לריפו פרטי**.
הקוד ממילא לא מעניין אף אחד; המחקר כן.

## 3.1 — ריפו פרטי · **אתה**

<https://github.com/new> → שם: `DAILY-BRIEF-content` → סמן **Private** →
אל תסמן שום תיבה נוספת → **Create repository**

## 3.2 — מפתח גישה · **אתה**

1. <https://github.com/settings/personal-access-tokens/new>
2. **Token name**: `daily-brief-content`
3. **Expiration**: שנה
4. **Repository access** → **Only select repositories** → בחר
   `DAILY-BRIEF-content`
5. **Permissions** → **Repository permissions** → **Contents** → שנה
   ל-**Read and write**
6. **Generate token** והעתק אותו
7. שמור אותו כ-secret בריפו הציבורי בשם `CONTENT_REPO_TOKEN`
   (אותו מסך כמו בסעיף 1.4)

## 3.3 — ההעברה · **אני**

מעביר את הברייפים והאינדקסים לריפו הפרטי עם כל ההיסטוריה, משנה את
הצנרת למשוך ולכתוב משם, ומכבה את GitHub Pages כדי שלא יישאר עותק פומבי.
